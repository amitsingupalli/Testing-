Level 1: Python Foundations Lesson 1.1 Intermediate ⏱️ 25 mins

Object-Oriented Agent Design & Patterns

Learn to encapsulate LLM client logic, dynamic memory states, and pluggable tool schemas into robust, production-grade Python agent classes.

🎯

Why this matters for AI Agents

In naive tutorials, AI agents are often written as monolithic scripts that paste user prompts into an OpenAI client and print the output. In production, this brittle approach rapidly degrades: tools throw unexpected exceptions, model outputs fail JSON parsing, and conversation tokens overflow memory limits.

Autonomous agents require modular, stateful architectures. An agent is a living state machine with perception (tool schemas), a brain (model inference), dynamic memory buffers, and action executors. Modern Object-Oriented design isolates tool contracts, standardizes state transitions, and wraps external API calls in strict error boundaries.

💡
Architect's Rule: An AI Agent is only as reliable as its error boundaries. Decoupling tool execution from model reasoning prevents single-tool failures from crashing entire multi-step workflows.

Concept explanation

Let's decompose the four fundamental pillars of every production-ready AI Agent architecture:

🧩 Tool Contract

Every tool is an isolated object inheriting from an abstract base class, exposing strict type schemas, execution logic, and automatic input validation.

🧠 Reasoning Core

The agent's decision engine that evaluates current context, plans step-by-step tasks, and selects tool invocations.

💾 State & Memory

Tracks short-term dialog history, intermediate tool observation logs, and long-term vector database references.

🛡️ Error Boundaries

Catches malformed tool arguments and runtime network timeouts, returning observation feedback to the LLM for self-correction.

When designing an Agent class in Python, avoid hardcoding LLM providers or specific tools inside the core class. Instead, use Dependency Injection: pass tools as a list of BaseTool instances, allowing agents to be configured dynamically for different operational tasks.

💻

Code example

Here is an end-to-end, production-grade implementation of an Object-Oriented Agent with dynamic tool registry and safe execution boundaries:

python 
from abc import ABC, abstractmethod
from typing import Dict, Any, List, Optional
import json

class BaseTool(ABC):
    """Abstract Base Class for all Agent Tools."""
    name: str
    description: str

    @abstractmethod
    def execute(self, **kwargs) -> Any:
        """Execute the tool action with validated parameters."""
        pass

    def to_schema(self) -> Dict[str, Any]:
        """Convert tool signature to OpenAI function calling schema."""
        return {
            "type": "function",
            "function": {
                "name": self.name,
                "description": self.description
            }
        }

class CalculatorTool(BaseTool):
    name = "calculator"
    description = "Safely evaluate basic mathematical expressions"

    def execute(self, expression: str) -> str:
        try:
            # Safe evaluation for basic math expressions
            allowed_chars = set("0123456789+-*/(). ")
            if not all(c in allowed_chars for c in expression):
                raise ValueError("Unauthorized characters in expression")
            result = eval(expression, {"__builtins__": None}, {})
            return str(result)
        except Exception as e:
            return f"Calculator error: {str(e)}"

class AutonomousAgent:
    """Production Object-Oriented AI Agent Engine."""
    def __init__(self, name: str, system_prompt: str, tools: Optional[List[BaseTool]] = None):
        self.name = name
        self.system_prompt = system_prompt
        self.tools: Dict[str, BaseTool] = {t.name: t for t in (tools or [])}
        self.memory: List[Dict[str, str]] = [
            {"role": "system", "content": system_prompt}
        ]
        self.step_count: int = 0

    def register_tool(self, tool: BaseTool) -> None:
        """Register a new tool into the agent runtime."""
        self.tools[tool.name] = tool

    def invoke_tool(self, tool_name: str, arguments: Dict[str, Any]) -> str:
        """Safely execute a tool with defensive error isolation."""
        if tool_name not in self.tools:
            return f"Error: Tool '{tool_name}' is not registered."
        try:
            return self.tools[tool_name].execute(**arguments)
        except Exception as err:
            return f"Tool Execution Failure [{tool_name}]: {str(err)}"

    def run_turn(self, user_input: str) -> str:
        """Simulate a single ReAct turn: Reason -> Act -> Observe."""
        self.memory.append({"role": "user", "content": user_input})
        self.step_count += 1
        
        # Step 1: Decision/Planning
        observation = ""
        if "calculate" in user_input.lower() and "calculator" in self.tools:
            # Simulating agent decision to invoke calculator
            expression = "144 * 12"
            observation = self.invoke_tool("calculator", {"expression": expression})
            self.memory.append({
                "role": "tool", 
                "tool_name": "calculator", 
                "content": observation
            })

        response = f"Agent {self.name} analyzed input. Observation: {observation or 'Direct response generated.'}"
        self.memory.append({"role": "assistant", "content": response})
        return response

# Example Usage:
if __name__ == "__main__":
    agent = AutonomousAgent(
        name="Athena",
        system_prompt="You are an autonomous mathematical reasoning agent.",
        tools=[CalculatorTool()]
    )
    result = agent.run_turn("Please calculate 144 * 12 for the payload calculation.")
    print(result)
▶ BaseTool (ABC): Enforces contract adherence so every tool consistently provides metadata schemas and safe execution methods.
▶ invoke_tool() Error Isolation: Catches unexpected tool exceptions internally, returning feedback strings instead of throwing unhandled exceptions.
▶ Structured Memory: Maintains conversational roles (`system`, `user`, `assistant`, `tool`) compatible with modern LLM chat formats.
